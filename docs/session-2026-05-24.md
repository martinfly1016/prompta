### 关键 feedback / 决策（本日实践沉淀）

- **「先验证 / 后判断」是 GA4 数据 review 标准动作** — 用户原指出 bounce 对列表页无意义，自查后发现真问题是 prompt-detail CTR 仅 2% (不是 bounce)。规范见 `_tag_engagement_probe.ts` 模式（landing-page filter + 流向分析）
- **「品牌风险」论需要 honest 拆解，不能用模糊词敷衍** — 我之前对 BL guide 套用「subculture brand 站队」论，被用户 push back 后逐项审视，发现实际具体风险只有 prompt 库 + cannibalization，其他都 ~0。从此约束「拆具体机制比生造概念更有用」
- **Semrush 月度 snapshot + GSC 数据交叉验证才能定位真大池** — Semrush 显示「身長差カップル」12.1K，GSC 只看到「身長差プロンプト」720 long-tail。如果只看 GSC 永远不知道真大池在 17x 上面。规范化：每周日报后必须 cross-check Semrush 大数据
- **BL「中立表現」策略 12/12 通過 SDXL safety filter** — `emotional bond between two men` / `close friends with romantic tension` 优于直接「BL/yaoi/gay」字面，全 22 件 batch 0 失败（女性化 0 件 + safety block 1 件被换）
- **「构図」vs「ポーズ」明确分轴** — BL 構図 guide = 整体画面 / BL ポーズ guide = 单姿势库；用乘法关系 cross-link 而非 cannibalize（30 ポーズ × 96 構図 = 2880 scenes）
- **Universal code-block copy button 与 markdown table renderer 都是 PR-内 universal fix** — 1 件 commit 解决全部 16 guide 的同类问题，ROI 比 per-guide 改强 10×
- **Cluster topology 强依赖 hub-vertical 拓扑** — 二人構図 hub 给所有 vertical (height-diff / BL / future 夢絵) 留位置，cluster effect 最大化
